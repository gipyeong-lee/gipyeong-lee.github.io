想像一下。您要求 AI：「幫我做一個會議用的彈出視窗」。AI 翻遍了它所學過的海量數據，組合出 50 多行複雜的 JavaScript 程式碼和 `<div>` 標籤，瞬間做出了一個彈出視窗。雖然可以運作，但總感覺它很笨重，且與瀏覽器設定不太相容。

事實上，現代網路瀏覽器已經具備了 2026 年的高階技術，但 AI 仍被困在 2019 年水準的「老舊習慣」中。Google 最近公開了一項工具，旨在解決這種令人沮喪的局面。[Show HN: Get your coding agent off ~2019 JavaScript, onto modern web primitives](https://github.com/GoogleChrome/modern-web-guidance)

### 這為什麼重要？

對於一般使用者來說，這聽起來可能很技術性，但我們每天使用的網站和應用程式的「舒適度」正是由這裡決定的。如果 AI 堅持使用舊方法，網站就會變得笨重、載入速度變慢，並且在智慧型手機或 PC 等各種裝置環境下，經常會發生畫面顯示異常的情況。

反之，如果 AI 使用現代網路技術，就能用寥寥幾行乾淨的程式碼，取代過去需要 50 行複雜 JavaScript 才能實現的功能。這對開發者而言意味著維護更方便，對使用者而言則意味著更快、更流暢的網路體驗。

### 簡單來說：「舊工具」與「新工具」的區別

現今的網路瀏覽器已經具備了極其強大的「內建工具」。打個比方，如果過去為了烤麵包，必須親自砌磚窯，那麼現在的瀏覽器就如同廚房裡已經完美內建了高性能的最新款烤箱。

然而，AI 明知這台烤箱的存在，卻傾向於習慣性地先拿出訓練數據中殘留更多的「砌磚法」。例如，當您想強調文字的特定部分時，與其逐一為 `<span>` 標籤添加樣式，不如使用名為 `CSS.highlights` 的現代功能，這樣會簡單得多。此外，在製作彈出視窗時，若使用瀏覽器基本提供的 `<dialog>` 標籤，而非複雜的 JavaScript，瀏覽器就能自動處理畫面置中或焦點管理等繁瑣的工作。

Google 公開了由網路專家直接編寫的 200 多份實作指南，旨在讓 AI 積極使用這些現代網路技術。[Show HN: Get your coding agent off ~2019 JavaScript, onto modern web primitives](https://github.com/GoogleChrome/modern-web-guidance)

### 現況：校正 AI 程式設計代理的「壞習慣」

目前許多 AI 模型都是受「慣性」驅動。為了導正這一點，Google 與建立網路標準的核心小組（包括 Firefox、MDN 和 Edge）進行了合作。[Show HN: Get your coding agent off ~2019 JavaScript, onto modern web primitives](https://github.com/GoogleChrome/modern-web-guidance)

該專案的核心之一是「遺留掃描（Legacy-scan）」。當 AI 試圖使用陳舊且佈滿灰塵的程式設計模式時，此功能能以約 92% 的準確度指出：「那種方式現在是舊方法了！」為了這項技術，Google 學習了約 3 萬個 GitHub（開發者分享程式碼的平台）儲存庫。[Show HN: Get your coding agent off ~2019 JavaScript, onto modern web primitives](https://github.com/GoogleChrome/modern-web-guidance)

### 未來會如何發展？

今後，AI 程式設計代理將會表現得越來越像一位「聰明的開發者」。它們將不再拖沓沉重的外部程式，而是充分利用瀏覽器所具備的強大基礎功能。這最終將帶來正面的改變，使我們所存取的網站速度更快、錯誤更少。AI 不僅僅是在生成程式碼，更是在邁向一個能根據網路未來標準設計程式碼的時代。
