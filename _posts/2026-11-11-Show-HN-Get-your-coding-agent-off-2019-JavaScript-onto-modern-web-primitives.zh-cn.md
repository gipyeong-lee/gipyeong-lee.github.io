想象一下：你请 AI“制作一个会议弹窗”。AI 在它学习过的海量数据中搜索，用 50 多行复杂的 JavaScript 代码和 `<div>` 标签组合拼凑出了一个弹窗。虽然能用，但总感觉很笨重，且与浏览器设置不太兼容。

事实上，现代 Web 浏览器已经具备了 2026 年的尖端技术，但 AI 依然困在 2019 年水平的“旧习”中。Google 最近推出了一款工具，旨在解决这种令人沮丧的情况。[Show HN: Get your coding agent off ~2019 JavaScript, onto modern web primitives](https://github.com/GoogleChrome/modern-web-guidance)

### 这为什么重要？

对于普通用户来说，这听起来可能很技术化，但我们每天使用的网站和 App 的“流畅度”恰恰由此决定。如果 AI 坚持使用老方法，网站就会变得臃肿、加载缓慢，且在智能手机或 PC 等各种设备环境中无法正常显示。

相反，如果 AI 使用现代 Web 技术，就可以用几行干净的代码取代以前需要 50 行复杂 JavaScript 才能实现的功能。这意味着对于开发者而言维护更方便，对于用户而言则意味着更快速、更顺滑的 Web 体验。

### 简单来说：“过时的工具”与“现代工具”的区别

今天的 Web 浏览器已经配备了强大的“内置工具”。打个比方，过去为了烤面包，你必须亲自垒砖砌灶；而现在，厨房里已经内置了性能卓越的现代化烤箱。

然而，AI 即使知道烤箱的存在，也习惯性地先使用训练数据中残留更多的“垒砖法”。例如，当你想强调文本的特定部分时，与其逐一给 `<span>` 标签添加样式，不如使用名为 `CSS.highlights` 的现代功能，这样会简单得多。此外，在制作弹窗时，如果使用浏览器原生提供的 `<dialog>` 标签，而不是复杂的 JavaScript，浏览器会自动处理屏幕居中、焦点管理等琐碎事务。

Google 为了让 AI 积极使用这些现代 Web 技术，公布了由 Web 专家直接编写的 200 多份实现指南。[Show HN: Get your coding agent off ~2019 JavaScript, onto modern web primitives](https://github.com/GoogleChrome/modern-web-guidance)

### 现状：纠正 AI 编码助手的“坏习惯”

目前许多 AI 模型是受“惯性”驱使的。为了纠正这一点，Google 与 Firefox、MDN、Edge 等 Web 标准制定核心组织进行了合作。[Show HN: Get your coding agent off ~2019 JavaScript, onto modern web primitives](https://github.com/GoogleChrome/modern-web-guidance)

该项目的核心功能之一是“遗留扫描（Legacy-scan）”。当 AI 试图使用老旧、灰尘覆盖的编码模式时，该功能可以以约 92% 的准确率指出：“那种方法已经是过去式了！”为了实现这一技术，Google 学习了约 3 万个 GitHub（开发者分享代码的平台）存储库。[Show HN: Get your coding agent off ~2019 JavaScript, onto modern web primitives](https://github.com/GoogleChrome/modern-web-guidance)

### 未来展望

未来，AI 编码助手将表现得越来越像“聪明的高级开发者”。它们将充分利用浏览器本身强大的原生功能，而无需硬搬笨重的外部程序。最终，这将带来积极的变化：我们访问的网站速度将更快，错误也将减少。AI 不仅仅是在生成代码，而是正在迈向一个根据 Web 未来标准设计代码的时代。
