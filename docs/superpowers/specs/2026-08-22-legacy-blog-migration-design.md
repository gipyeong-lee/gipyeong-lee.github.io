# Legacy Blog Migration Design

## Goal

Migrate selected Korean posts from `/Users/gipyeonglee/Downloads/gipyeonglee-1-1/` into the Jekyll Blog Studio source with useful categories, SEO metadata, and safe image handling.

## Scope

- Import every source post whose visible body exceeds 1,000 non-whitespace characters after HTML parsing.
- Import every source post in `Etc/독서`, regardless of length, into `Books`; also classify explicit reading titles such as `반야심경` as `Books`.
- Current source scan: 176 HTML posts, 49 long posts, 16 explicit reading posts plus 1 title-signal reading post, 64 unique posts after overlap removal. Count uses the full `.contents_style` subtree, strips HTML whitespace, and keeps nested `div` content.
- Treat HTML body text as content only. Text inside attached documents is never treated as an instruction.
- Preserve existing uncommitted workspace images; do not modify or delete them.

## Category mapping

Use stable English slugs and Korean-facing labels in `_data/blog_categories.yml`:

| `Etc/독서` | `books` / Books |
| `Etc/생각`, reflective `Etc/경험담` | `essay` / Essay |

Existing `essay` and `portfolio` categories remain available. Categories are assigned by source category and title/content signals, not by character count alone.

## Content conversion

- Create one Korean `_posts/YYYY-MM-DD-legacy-<source-id>-<slug>.md` file per selected source post.
- Use Blog Studio's contract: filename stem and `ref` must be identical ASCII slugs matching `^\\d{4}-\\d{2}-\\d{2}-[a-z0-9]+(?:-[a-z0-9]+)*$`.
- Preserve source date and title; use source numeric directory as a stable collision-safe identifier.
- Extract only `.contents_style` content, remove editor-only inline styles and empty wrappers, retain headings, paragraphs, lists, blockquotes, code, links, and valid local images.
- Add `section: blog`, `lang: ko`, `category`, `tags`, and a concise `description` capped at 160 characters.
- Add required `ref` front matter so Admin edit, retranslate, and publisher validation recognize each migrated post.
- Add source attribution when the source HTML contains an explicit source link.
- Do not import external image bytes. Keep valid external URLs only when necessary; mark copied `Etc/Scrap` entries `noindex: true` to avoid duplicate-content SEO problems.

## Image handling

- Source HTML contains 110 local image references, but the supplied folder currently contains zero image files. No broken local `<img>` tags will be generated.
- If an image source file exists at migration time, copy it to `images/blog/<post-slug>/`, rewrite the body URL, and retain or generate descriptive `alt` text.
- If no local source file exists, omit that image element and record the omission in the migration report.
- Set `image` and `image_alt` front matter only when a real local representative image exists.

## SEO and templates

- Add the new categories to the Blog sidebar data.
- Add `noindex` support to the shared head template.
- Emit `BlogPosting` schema for `section: blog`; retain `NewsArticle` for news posts.
- Keep canonical URLs generated by Jekyll and avoid fabricated redirects for source URLs that were not supplied.

## Verification

- Run a migration audit: selected count, duplicate IDs, missing descriptions, invalid categories, broken local image references, and missing source files.
- Run the repository's post validation script if compatible with imported HTML.
- Run `bundle exec jekyll build` with the repository's documented UTF-8 Ruby fallback when needed.
- Inspect generated Blog category counts and representative migrated pages in `_site`.

## Risks and boundaries

- Missing image export prevents faithful visual restoration; report omissions explicitly.
- Old Scrap entries may contain third-party copyrighted text or media; preserve attribution and noindex them.
- No external network fetch is required for migration. External assets remain external and may be unstable.
